# Contributing to awesome-best-ai-2026

Thanks for helping improve this list.

## Submission Rules

Every submission must include:

- A canonical public `github.com/owner/repo` URL
- A short summary of the tool
- Current GitHub stars
- Primary language
- License as shown on GitHub
- Last commit date
- Category tags
- A short `Best for` use case

## What We Accept

- Open source AI tools with a public GitHub repository
- Self-hosted AI platforms, coding tools, workflow systems, media tools, SDKs, and integrations
- Repositories with clear usefulness beyond a thin demo or placeholder

## What We Reject

- Proprietary SaaS products without a public GitHub repository
- Tools whose primary URL is not on `github.com`
- Repositories with missing or unclear licensing when no verification is provided
- Dead links, duplicates, forks without meaningful differentiation, and obvious spam

## Pull Request Format

Use this format in your pull request description:

```md
### Tool Name
- GitHub: https://github.com/owner/repo
- Description: One or two sentences
- Stars: 1234
- Language: TypeScript
- License: MIT
- Last Commit: 2026-03-30
- Category: workflows, agents
- Best for: self-hosted automations
```

## Quality Standard

Keep entries specific. Do not submit vague “AI platform” descriptions when the repository has a clear scope. If a category is sparse, document the gap instead of forcing weak entries into the list.

## Local Checklist

- Update `README.md`
- Keep the list alphabetized within a category when practical
- Verify the GitHub URL works
- Verify the metadata before opening the PR
